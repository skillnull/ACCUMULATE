# 文本省略与兼容

适用：各端、各编程语言及框架中的单行、多行省略，以及缩字号后的截断。先确认运行时、渲染引擎和最低版本；移动端最低版本沿用主规则，其他环境按项目约定验证。

## 通用选型

1. **原生能力优先**。先查目标项目已有组件及运行时的文本截断、行数限制和布局能力。保留完整原文，不为普通省略预先自制测量或裁剪字符串；不把 CSS、DOM、Hook 或某种语言作为共同前提。
2. **分别验证截断与对齐**。真实末行、截断后的可见末行和省略号位置分别检查。某平台的属性、组件或一次成功不证明其他端等效；不得用左对齐、换字体或改变内容静默替代既定需求。
3. **复现后再选择回退**。记录目标系统、运行时/渲染器版本、字体、尺寸、原文及异常证据，先排查约束、继承和发布产物。原生实现仍不满足时，按允许范围采用最小的本端测量或布局回退；参考 [跨端文本省略与动态排版](../references/text-ellipsis-layout.md)。不得仅凭“旧环境可能有问题”替换原生实现。
4. **字号自适应单独处理**。只有明确要求“先缩字号，到下限再省略”时，才启用 [字号自适应流程](../references/auto-fit-text-component.md)。其中 Web API 只是对应端的适配方式。
5. **按目标端实现**。复用排版约束与验收目标，采用目标语言、框架的测量和生命周期。没有排版上下文的服务端不能凭字符串长度保证视觉行数；字符数限制需另行明确字符、字素或字节口径。

## 通用约束

- 文本层具备有效尺寸约束；按目标布局系统处理可收缩宽度、溢出和裁切。交互、完整原文与可访问性保持原契约。
- 使用实际字体、字重、字号和行盒度量；独立尾部必须预留空间，不能覆盖正文。混合行高或富文本以实际各行布局为准，不机械套用统一行高。
- 字号、行高、内容、容器、缩放、样式、资源加载及显隐变化后，使用本端可观察的布局事件刷新；合并重复任务，防止自身写入循环触发，销毁时释放资源。
- 确需裁剪字符串时，明确语言的字符编码与字素边界；不得截断多字节字符、代理对或组合字符。行尾方向按目标文本方向处理，不将物理右侧当作所有语言的行尾。

## Web 适配

- 单行可用 `white-space: nowrap`、`overflow: hidden`、`text-overflow: ellipsis`；flex/grid 文本项核对 `min-width: 0`。
- 原生多行在同一文本层使用 `display: -webkit-box`、`-webkit-box-orient: vertical`、`-webkit-line-clamp: N` 和隐藏溢出，核对构建后声明仍在；低版本不单独依赖无前缀 `line-clamp`，也无需额外叠加 `text-overflow`。
- 允许 `text-align: justify` 与原生省略组合，以目标环境实测为准；不能依赖 `text-align-last` 覆盖 iOS 10。换行策略按内容选择，不未经复现就认定 `break-all` 或按钮必然造成故障。
- 点击控件与文本截断层分工；自定义 slot/SVG 必须检查最终文字层，末字截半或硬裁切不算省略成功。Web 浮动占位回退见参考中的条件案例，不能套到原生控件或无 DOM 的运行时。

## 验收

- 覆盖空文本、未溢出、刚好容纳和超过限制；只有溢出时出现省略号。逐行核对数量、尾部避让及所需对齐，短文本不异常拉伸。
- 覆盖本次支持的文字、混排、连续长串、标点及文本方向；确认实际字体和回退。验证字号放大再还原、独立行高变化、尺寸变化、内容更新和隐藏恢复；省略状态须能出现和取消。
- 在目标端最低版本和真实宿主验证，记录框架/引擎、系统及设备或模拟器范围；检查性能与资源释放。类型检查、构建或某台设备成功不能代替其他端验收，未验证范围明确记录。
