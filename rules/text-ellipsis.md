# 文本省略与兼容

适用：单行、多行文本省略，以及字号缩至下限后的截断。最低兼容安卓 7 与 iOS 10。

## 方案选择

1. **优先 CSS 原生省略**。固定字号文本使用 `text-overflow` 或 `-webkit-line-clamp`，DOM 保留完整原文。不预先创建测量节点、裁剪字符串或手动拼接省略号。
2. **按需求设置对齐**。允许 `text-align: justify` 配合原生多行省略，以目标环境实测为准，不设统一禁令。真实末行与截断后的可见末行要分别验证；不能依赖 `text-align-last` 覆盖 iOS 10。
3. **实际复现后再考虑 JS**。先记录目标系统、浏览器/WebView 版本、字体、容器宽度、原文及异常截图。排查最终样式、继承、构建产物和布局约束，验证最小 CSS 修正。原生方案仍不能满足需求时，才考虑范围最小的 JS 回退；不得仅凭“旧 WebView 可能有问题”替换原生方案。
4. **字号自适应单独处理**。只有明确要求“先缩字号，到下限再省略”时，才使用 [自适应字号文本组件](../references/auto-fit-text-component.md) 的测量流程。普通单行或多行省略不触发该流程。

## CSS 实现约束

- 宿主及必要中间层具备有效宽度约束；flex/grid 文本项设置 `min-width: 0`，文本层限制最大宽度并隐藏溢出。点击控件负责交互，截断样式优先放在内部普通块级文本层。
- 单行使用 `white-space: nowrap`、`overflow: hidden`、`text-overflow: ellipsis`。
- 多行在同一文本层使用 `display: -webkit-box`、`-webkit-box-orient: vertical`、`-webkit-line-clamp: N`、`overflow: hidden` 和明确行高。核对构建后声明仍在；兼容低版本时不单独依赖无前缀 `line-clamp`。多行省略无需额外设置 `text-overflow: ellipsis`。
- 换行策略按内容设置并检查继承。普通中文文本可用 `word-break: normal` 与 `word-wrap: break-word` 作为基线；兼容低版本时不依赖 `overflow-wrap: anywhere`。不得未经复现就认定 `break-all`、按钮或对齐方式必然导致省略号丢失。
- 自定义 slot/SVG 的省略须检查最终文字层，不能仅凭父容器的 `text-overflow` 判断成功；末字截半或硬裁切不算省略已实现。

## 验收

- 覆盖未溢出、刚好容纳和超过限制的文本；只有溢出时出现省略号。多行检查实际行数、行尾空隙、末字及省略号，按需求核对两端对齐，不以固定“几个字宽”代替判断。
- 覆盖中文、数字/英文混排、连续长串及相关容器宽度；确认字体与最终计算样式。字号自适应另按对应参考验收。
- 兼容结论附实际验证的系统和浏览器/WebView 版本。用户确认某台真机正常，不推广为全部版本通过；未在真机复测时明确缺口。
