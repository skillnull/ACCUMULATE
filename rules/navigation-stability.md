# 路由与容器导航稳定性

适用：路由定义、目录迁移、路由枚举/模板改写、页面跳转、WebView 和离线包的变更或故障排查。

## 已暴露的缺陷与证据边界

- 稳定路径改写为枚举引用时，模板漏写 `{`，会把变量名注册成字面量路径。语法检查可通过，但原公开路径已改变。
- `location.origin + location.pathname` 不适用于所有容器。`file:` 页面 origin 为 `"null"` 时，会生成 `null/…` 错误地址。
- 名称导航成功不证明预期路径、冷启动或原生打开成功；字符串模拟也不证明客户端能够加载本地文件。代码缺陷与实际故障根因须分别举证，未取得设备实际协议、地址及失败证据，不得认定离线包是唯一根因。

## 强制约束

1. **保持导航契约**：无需求依据不得为统一风格改写稳定路由、切换同容器导航与新开 WebView，或改变返回、参数、来源页状态和离线资源加载语义。确需调整时先确认目标行为并回归受影响入口；不因本规则新增审批环节。
2. **核对运行时路径**：路径改写前后比较实际求值结果。静态路径须保持一致；动态路径验证代表性参数。必须同时核对名称解析与预期 URL 路径解析，检查路由注册、组件导入和资源路径；不得只看模板文本、名称匹配或编译通过。
3. **安全生成地址**：优先复用现有导航封装及原生协议，不假定 origin 总是 HTTP(S)。Hash 路由仅需替换 hash 时，可保留 `location.href.split("#")[0]` 再接路由器生成的 hash；仅在路由模式与生成结果吻合时使用。保留协议、入口和约定参数，查询参数由路由器或现有工具编码，禁止整条 URL 重复编码。
4. **验证原生契约**：新开 WebView 须核对指令、字段、URL 协议及文件访问支持。地址合法不代表原生支持；不擅自把离线地址改为线上地址，也不把新开 WebView 当成页面内路由的等价替换。

## 回归与交付门槛

- 从原始入口点击跳转，覆盖直接打开/刷新、参数解码和返回来源页。模板路径改写须断言解析出的路径等于预期路径，再检查匹配的页面；同一错误配置的自洽匹配不算通过。
- 对本次支持且受影响的环境分别验收：浏览器、客户端在线页面、离线包。离线包验证实际协议、入口及资源加载；客户端验证打开指令、页面和返回行为。覆盖约定的失败/空数据路径，不靠新增固定延时掩盖问题。
- 交付区分代码检查、模拟回归、浏览器实测和设备实测。未具备客户端或离线包环境时，明确缺口，不得声称三端通过、问题已在设备解决或保证无问题。
