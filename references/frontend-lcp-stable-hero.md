# 前端 LCP 稳定首屏优化

用于定位和修复以下问题：FCP 已经较快，但 LCP 仍明显偏高；首屏主视觉依赖框架启动、异步路由或接口完成后才出现；远程图片需要优先加载并兼容旧浏览器；优化过程中必须保持既有业务加载与交互契约。

## 交付原则

1. **性能优化不得改变需求逻辑和既有加载契约**
   - 优化前先列出业务不变量，至少包括首屏数据请求、实时数据订阅、图标和关键交互组件、鉴权、Bridge 初始化、错误态与重试时序。
   - 原本随页面自动加载的依赖，不能为了降低 LCP、TBT 或包体积改成点击、展开、弹窗打开或进入视口后才加载。
   - 实时数据 WebSocket/订阅和首屏所需图标库必须保持自动加载，除非用户明确批准新的产品加载契约。
   - 不得擅自删除或缩短接口、Mock、超时、重试、loading、权限和异常处理逻辑。

2. **先区分资源慢、节点晚出现和主线程阻塞**
   - 不要只看 LCP 总时长。结合 LCP 元素、请求发起与完成时间、元素进入 DOM 的时间、长任务和路由/组件执行时间判断瓶颈。
   - 资源请求本身很晚：优化发现时机、连接、优先级、格式和尺寸。
   - 资源已下载但 LCP 仍晚：排查异步路由、框架启动、懒编译、接口状态、`v-if`、组件挂载和节点替换。
   - LCP 与 TBT 同时偏高：排查主包、路由 chunk、重依赖解析执行和长任务，但不能用延后业务关键依赖来掩盖问题。

3. **LCP 不是唯一交付指标**
   - 同时记录 FCP、LCP、TBT（实验室）或 INP（真实用户）、CLS、应用可用时间、关键订阅启动时间和控制台/网络错误。
   - 如果静态首屏把 LCP 提前了，但真实内容或首个关键交互仍明显晚，只能判定为“LCP 路径已改善”，不能判定整页性能已经完成。

4. **首屏主视觉不依赖业务接口**
   - 纯视觉背景、固定尺寸容器和不会随接口改变的基础内容应在业务接口完成前可见。
   - 参与状态、权限、实时数据、阶段判断、弹窗和跳转仍按原有逻辑执行，不得为了提速移动、删除或伪造业务状态。
   - 初始化加载态应避免先出现错误视觉或大面积空白，再被最终视觉替换。

5. **业务优化必须留在业务模块，共享 HTML 入口没有业务特例**
   - 业务路由模块负责自己的资源提示、轻量首屏、生命周期和样式；这是默认且必须优先的实现路径。
   - 任何业务模块都不得把新的路由判断、图片地址、DOM 模板、脚本或样式插入共享 `index.html`，也不得通过构建配置间接生成这些业务内容。
   - 该禁令不授权清理历史存量。发现已有业务入口内容时保持原样并记录；只有用户明确要求迁移或删除后才能处理。
   - 即使框架启动超过 LCP 预算，也不能用业务入口壳绕过约束。应继续优化业务路由、轻量入口组件、资源发现、共享启动链和依赖执行成本。
   - 如果模块内方案仍无法达到预算，应如实报告剩余瓶颈和架构限制，不能通过污染共享入口制造更好的指标。

## 先做业务依赖分级

| 分级                 | 典型内容                                                            | 处理规则                                                       |
| -------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------- |
| 首屏业务关键         | 实时数据订阅、首屏接口、鉴权、Bridge、首屏图标和即时可用的弹窗/按钮组件 | 保持原有自动加载和执行时序，只优化实现成本，不改成“交互后加载” |
| 首屏视觉关键         | 主视觉背景、标题区域、固定布局、首屏可见图片                        | 提前发现、提高优先级、使用最终资源直接绘制并预留尺寸           |
| 非首屏且原本允许延后 | 首屏以下图片、未展开区域、产品契约本来就是按需加载的内容            | 可懒加载、异步组件或降低优先级                                 |
| 未确认               | 可能影响埋点、业务状态、错误处理或用户首个动作的依赖                | 默认保持现状；先确认需求再调整                                 |

“代码上可以异步”不等于“产品上允许延后”。把现有 eager 依赖改为交互触发属于需求变化，不是中性的性能优化。

## 按作用域分层，避免把业务优化误做成全局能力

| 作用域     | 适合优化的内容                                   | 推荐方式                                                          | 不变量                                                               |
| ---------- | ------------------------------------------------ | ----------------------------------------------------------------- | -------------------------------------------------------------------- |
| 共享启动链 | 未被当前路由使用的非观测类全局能力、开发编译配置 | 确认产品契约后保留轻代理；开发验收环境预编译入口                  | 不调整监控、RUM、行为分析等观测 SDK 的加载顺序；不包含业务路由和图片地址 |
| 业务路由   | 目标 CDN 连接、LCP 图片 preload、轻量路由壳      | 按首路由精确命中并去重，路由守卫处理站内进入                      | 未命中路由零专属请求、零专属 DOM；不得写入共享 HTML                  |
| 首屏视觉层 | 最终主视觉、标题区和固定布局                     | 原生 `<picture>/<img>`、明确尺寸、WebP 回退、eager 和高优先级     | 不等待业务接口；不得用临时大节点伪造 LCP                             |
| 业务内容层 | 接口、鉴权、实时数据、Bridge、弹窗和阶段判断         | 必要时立即异步加载，使用 Suspense/loading 保持原状态              | 页面渲染即启动，不等待用户交互；原错误、重试和跳转时序不变           |
| 非首屏内容 | 长图、规则、介绍和低优先级操作依赖               | 合理裁剪、原生 lazy、收紧预取距离；操作专属代码可在操作发生时加载 | 只处理产品本来允许延后的内容，不与 LCP 抢带宽                        |

“全局优化”只允许处理与具体业务无关的共享启动成本。业务图片、业务路由判断和业务首屏壳即使被多个页面采用，也必须分别留在各自模块；不得为了复用而建立全局业务资源注册表。

## 推荐实施顺序

### 1. 固定基线与业务不变量

在改代码前记录：

- 实际设备或目标移动端视口。
- 网络、CPU、缓存、登录态、App 查询参数和业务阶段。
- LCP 元素、FCP、LCP、TBT、CLS、关键请求与订阅启动时间。
- 首屏无需点击就必须出现或启动的内容。
- 其它路由不能新增的资源或行为。

测试地址不得使用真实 Token、手机号或其它用户数据。使用脱敏参数或本地测试值。

### 2. 确认实际 LCP 元素和延迟类型

使用浏览器 Performance、Lighthouse 明细或 `PerformanceObserver`，至少确认：

- LCP 节点类型、图片 URL、元素尺寸和渲染时间。
- 图片请求发起时间、优先级、下载完成时间和请求次数。
- 接口完成前后是否创建、隐藏或替换主视觉节点。
- 长任务、主包、路由 chunk、样式和重依赖的加载执行时间。
- 带不同查询参数和业务阶段时是否走了不同分支。

必须在目标视口复测。接近整屏、被浏览器判断为背景或低信息量的图片可能不会成为 LCP 候选；不能只根据肉眼最大元素推断 LCP。

### 3. 提前连接并预加载最终资源

对已经确认的 LCP 图片：

- 对图片 CDN 添加 `preconnect`，必要时补 `dns-prefetch`。
- 添加 `preload as="image"` 和 `fetchpriority="high"`。
- 预加载 URL 必须与最终 `currentSrc` 完全一致，包括格式、裁剪、质量、宽度和查询参数，防止重复下载。
- 只预加载一个最终会选中的格式，不同时抢占 WebP 和 PNG/JPEG。
- 资源提示必须按首路由精确命中，不能污染其它路由。

Hash 路由不会发送给服务端，需要在业务路由模块中读取 `location.hash`。匹配规则应同时覆盖合法查询串并避免前缀误命中，不得把判断放入共享 `index.html`。

如果必须达到 HTML 解析期的资源发现时机，但不能修改共享 `index.html`，优先评估由网关、CDN 或源站按请求返回 `Link: <...>; rel=preload; as=image`，支持时可配合 `103 Early Hints`。Hash 不会出现在 HTTP 请求中，因此服务端必须依赖真实路径、独立域名或显式查询参数精确识别目标页面；没有服务端可见标识时，不得对共享入口无差别下发业务资源提示。

优先由业务目录提供声明式资源清单，并在已有业务路由注册模块中按首路由精确触发；共享层只提供无业务判断、无自动扫描、无副作用的资源提示工具。不得为了单个业务预加载修改全局入口，或让所有路由同步遍历业务清单。只有多个业务明确复用且完成全路由同条件回归后，才可引入通用注册器；注册器不得硬编码业务路由或资源地址，未命中时不得创建专属链接、发起专属请求或改变应用启动语义。单个业务清单异常必须隔离，不能阻断其它路由启动。资源链接应按规范化后的绝对 URL 去重，避免首路由触发与路由守卫重复插入。

### 4. 使用远程 WebP 与兼容回退

远程活动图需要动态替换时，继续使用稳定 CDN 地址，不复制进源码、构建产物或 Base64。优先使用原生 `<picture>`：

```html
<picture>
  <source srcset="远程图片?x-oss-process=image/format,webp" type="image/webp" />
  <img
    src="远程原图"
    width="750"
    height="520"
    loading="eager"
    decoding="async"
    fetchpriority="high"
    alt=""
  />
</picture>
```

- WebP 用于支持的浏览器，`<img>` 保留 PNG/JPEG 回退。
- 声明真实 `width`、`height` 或固定宽高比，预留布局空间并控制 CLS。
- 纯装饰图使用空 `alt`，有业务含义的图提供准确替代文本。
- 用 Network 的 `currentSrc` 和实际请求验证格式，不能只根据代码推测。

### 5. 优先建立业务模块内的轻量首屏

当异步路由或重组件拖延 LCP 时，优先采用：

1. 让目标路由的轻量首屏进入框架首个渲染周期。
2. 同步部分只包含主视觉、固定布局和必要状态。
3. 首屏以下内容只有在原产品契约允许时才异步或懒加载。
4. 主视觉不等待业务接口；接口继续控制原有业务区域和动态信息。
5. 控制同步依赖范围，避免把完整页面和重依赖全部塞进主包。

实践中可以把最终主视觉留在同步路由壳，将原业务内容放入立即加载的异步组件并用 `Suspense` 承接原 loading。拆分后必须逐项对照接口请求、鉴权、实时数据订阅、Bridge、页面可见性监听、错误态和返回刷新逻辑，不能只验证视觉出现得更早。

### 6. 框架启动过晚时仍在业务模块内解决

当资源很早完成、但 Vue、路由或开发懒编译导致可绘制节点晚数秒出现时：

1. 在业务路由模块命中目标路径后立即注册 CDN `preconnect` 和最终图片 `preload`。
2. 同步加载一个极轻的业务路由入口组件，让它直接输出最终 `<picture>`；重业务页面由该组件立即异步加载，不等待用户交互。
3. 最终图片由轻量入口组件持续持有，业务页面覆盖在其上方，不做占位节点到正式节点的替换。
4. 检查共享启动链中的同步长任务和无关初始化，但不得改变鉴权、监控、RUM、行为分析、实时数据或其它既有业务契约与加载顺序。
5. 开发环境 lazy compilation 造成的编译等待需要单独标注，不能通过向共享 HTML 写业务内容规避。若首路由连应用入口也等待懒编译，可在开发性能验收环境预编译入口、保留异步业务模块按需编译，例如 webpack 使用 `lazyCompilation: { entries: false, imports: true }`；这只用于移除开发编译噪声，不代表生产 LCP 已改善。
6. 模块内优化后仍未达标时，报告真实瓶颈和架构限制，继续处理启动链或依赖成本。

不得只为提前执行资源预加载，把所有路由原有的同步启动链改成额外的异步加载跳数。确需调整共享启动链时，必须证明未命中路由的启动时序、请求集合、业务初始化和错误处理没有回归，并对已有重点路由做同条件复测。

### 6.1 共享启动链的安全减负

仅当依赖不参与首屏 DOM、首屏样式、鉴权结果、观测链路或首次业务决策时，才可从同步主包拆出：

- 监控、RUM、行为分析等观测 SDK 默认保持既有同步导入、初始化和用户信息设置顺序。不得把它们作为通用 LCP 手段改成动态导入、首帧后、空闲时或交互后加载；如确需调整，必须由用户明确批准，并先证明启动期错误、首路由、PV/UV、自定义事件、用户标识、资源与 Web Vitals 数据均不丢失。
- 全局注册但多数路由不使用的重指令，可以同步注册轻量代理，在元素 `mounted` 时自动加载真实实现。加载 Promise 必须去重，并转发生命周期；元素先卸载时不得补挂载或泄漏订阅。
- 实时数据指令或实时数据 SDK 的拆包只改变代码获取方式，不改变业务触发条件。使用该指令的元素一挂载就必须开始加载并建立订阅，不能等待用户交互。
- 操作专属且不影响首个可用状态的代码，例如只在点击后执行的跳转辅助函数，可以在对应操作内动态加载；图标、实时数据、鉴权和首屏按钮本身不属于此类。
- 每个获准的全局拆包都要核对请求是否仍自动发起、初始化是否只执行一次、异常是否可见、卸载是否清理，并回归至少一个使用该能力的路由和一个不使用的路由。

立即异步加载的收益是让首屏渲染不再等待依赖解析执行，不等于减少总下载量。若异步 chunk 仍与 LCP 资源争抢带宽，需结合瀑布图继续调整，不能仅凭“已经拆包”判定完成。

### 7. 路由拆分只作补充

可以在业务模块内使用“轻量同步入口 + 立即异步业务页面”减少主视觉等待，但要注意：

- 轻量入口只能包含最终视觉和必要布局，不能把完整业务页同步打入所有路由的主包。
- 异步业务页面必须随路由渲染立即加载，不能改成点击、展开或进入视口后加载。
- 开发环境启用 webpack lazy compilation 时，业务 chunk 仍可能等待开发编译器。
- 是否拆包应结合解析/执行成本、缓存复用和网络瀑布判断，不能只看单个 chunk 大小。
- 禁止使用构建配置向共享 `index.html` 注入目标业务的 preload 脚本或资源映射。

不要默认“每个业务一个入口”。独立入口只在以下条件同时成立时考虑：

- 页面有服务端可见的独立路径、域名或入口参数，不依赖 Hash 猜测。
- 现有公共启动链是已测量的主要瓶颈，独立入口能显著减少首屏必须下载、解析和执行的代码，而不是只省少量路由声明。
- 独立入口仍复用统一鉴权、监控、Bridge、埋点和错误处理契约，并能承担额外的模板、缓存、发布和回归成本。
- 同条件冷启动至少 3 次的中位数证明 LCP 和应用可用时间有明显收益，且其它入口无回归。

如果主要收益只是更早发现一张图片，优先使用服务端 `Link`/`103 Early Hints` 或业务模块内资源提示，不为此拆分多入口。

### 8. 降低非首屏资源竞争

只对产品契约本来允许延后的资源使用：

- 首屏以下图片 `loading="lazy"`、合理 `root-margin`、远程裁剪和质量控制。
- 非关键请求降低优先级或在首屏稳定后执行。
- 项目已有图片组件满足需求时直接复用，不重复实现。

复用图片组件前检查其实际渲染时机和属性透传。若组件默认懒加载、只在 `mounted` 后创建 `<img>`，或不透传 `loading="eager"`、`fetchpriority="high"`、`decoding`，它不适合作为 LCP 最终节点，也不能替代路由期 preload；此时使用原生 `<picture>/<img>` 是浏览器能力组合，不视为重复造业务轮子。

不要用过大的预取距离提前请求全部长图，也不要把首屏必须自动建立的实时数据订阅归类为非关键资源。

对于纵向活动页的大图列表，优先请求与展示宽度匹配的远程尺寸，并把 `rootMargin` 控制在能覆盖正常滚动速度的范围。预取距离从数百像素收紧后，要验证快速滚动不会看到空白；URL 已包含尺寸参数时，还要确认图片组件不会再拼接出无效或重复的处理参数。

## 推荐组合：业务模块内轻量首屏

1. 目标路由同步加载轻量首屏组件，避免主视觉等待重业务 chunk。
2. 轻量首屏用带明确尺寸的 `<picture>` 输出最终主视觉，优先使用远程 WebP，并保留兼容格式。
3. 在业务路由模块内精确命中当前路径后添加 CDN `preconnect` 和最终图片 `preload`；其它路由不得触发专属请求。
4. 接口、鉴权、Bridge、实时数据、弹窗和复杂内容留在异步业务组件内，保持原有自动加载和执行时序。
5. 首屏以下图片继续使用懒加载、合理 `root-margin`、远程裁剪和质量控制，避免与 LCP 图片争抢带宽。
6. 同时检查 LCP、CLS、TBT、业务可用时间和关键交互，不能只看单次 Lighthouse 分数。

业务模块不得把路由判断、图片地址、DOM 模板、脚本或样式写入共享 `index.html`，也不得通过构建配置间接注入。没有业务特例。模块内方案仍无法满足预算时，应报告真实瓶颈并继续优化启动链和依赖成本。

## 验证与交付标准

### 性能复测

- 基线与优化后必须使用相同视口、网络、CPU、缓存、URL 参数和数据分支。
- 使用全新浏览器配置或明确清缓存，至少执行 3 次冷启动；报告中位数，必要时补充最差值或 P90。
- 记录 FCP、LCP、TBT/INP、CLS、应用可用时间、LCP 节点、关键资源瀑布和订阅启动时间。
- 确认 LCP 图片只请求一次、优先级正确、`currentSrc` 与 preload 一致。
- 区分开发编译等待、资源下载、JS 解析执行和真实页面渲染，不用一个综合分数代替诊断。

### 业务回归

- 无需点击，实时数据订阅仍会自动建立。
- 首屏所需图标和关键按钮立即可见，弹窗等原有交互首次点击即可使用。
- 接口、Mock、loading、错误态、权限、重试、Bridge 和埋点时序未被擅自改变。
- 主图尺寸、动态覆盖层、文字位置、点击事件、滚动、吸顶和路由离开行为正常。
- 非目标路由不加载专属 LCP 资源。
- 共享预加载工具不扫描业务清单且自身无副作用；未命中路由时不新增 DOM 链接或网络请求，不改变原有路由与应用初始化顺序。
- 全局监控、RUM、行为分析的导入、初始化、用户信息设置和首个事件顺序与改动前一致；不能只验证 SDK 文件成功下载。
- 实时数据指令所在元素挂载后无需交互即可加载实现并建立订阅；快速挂载再卸载不会产生迟到订阅或清理异常。
- 至少回归根路由、目标路由和一个已有重点业务路由；核对页面挂载、专属资源隔离、重复 preload/preconnect 与新增控制台错误。

### 工程检查

- 检查控制台和 Network 错误、重复请求、未使用 preload、内存/订阅清理。
- 检查共享 `index.html` 和构建模板，确认本次没有新增任何目标业务的脚本、模板、图片、样式或资源映射；不得借检查之名删除历史存量。
- 执行受影响文件的 ESLint、Stylelint、格式化检查和 `git diff --check`。
- 用户要求只在开发环境测试时，不强制执行构建；必须在结果中标明开发环境及 lazy compilation/HMR 对数据的影响。
- 需要生产发布结论时，再在获得授权后补充生产构建或生产等价环境数据。

## 禁止的无效或高风险做法

- 把实时数据订阅、图标库、首屏接口、鉴权或关键交互组件改成点击/展开后加载来换取分数。
- 删除或缩短业务接口、Mock、超时、重试、loading、权限或异常处理逻辑。
- 只转换 WebP，却不处理接口、框架或异步路由导致的节点晚挂载。
- 把可动态替换的远程运营图放进本地包或转成 Base64。
- 以任何理由向共享 `index.html` 添加特定业务的路由判断、脚本、模板、图片或样式，或在未获明确授权时清理历史存量。
- 通过构建配置、模板参数或生成脚本间接向共享 `index.html` 注入特定业务内容。
- 只为提前执行预加载，把全局同步入口改成额外异步跳数，却没有验证其它路由启动回归。
- 为单个或少数业务在全局入口同步扫描全部业务资源清单，给未命中路由增加启动成本。
- 在普通隐藏 DOM 中放路由专属图片，误以为 `display: none` 能阻止请求。
- 预加载一个 URL，最终组件请求另一个 URL，造成双重下载。
- 用无关骨架、大文本、透明元素或瞬时占位图制造假的 LCP 候选。
- 框架挂载后把同尺寸最终主图替换成另一个节点，导致新的 LCP 或视觉闪动。
- 只看一次 Lighthouse 分数，不核对 LCP 节点、资源瀑布、业务可用时间和关键依赖启动时序。
